# Operational and security constraints

- Installed JavaScript and explicit native tool/shell delegation are trusted. Coordinator containment is not a shell sandbox.
- Only genuine official conversation/service configurations authorize hosted capabilities. Codex subscription auth is separate from paid conversation API credentials and Fast priority costs. No paid hosted-capability fallback.
- Runtime status is passive, not proof of authority, entitlement or free capacity. Unknown host/helper/platform conditions fail closed.
- Exact native context/scope identity, not guest fields or IDs, owns returned resources and references. Never repair failed publication or clear draining/lock ownership based on apparent PID death.
- New profiles and side-by-side immutable bundles only. No global installation changes, automatic credential import, active settings overwrite or history/original deletion.
- Pin and verify upstream, native patch, catalog, license, lock, compiler/reference inputs and helper. No runtime compilation/download or unrestricted fallback.
- Do not run live-provider upstream test suites. Routine tests use offline/faux/mocked service seams and do not establish account entitlement.
- Keep credentials, private audit material, user artwork and local receipts out of Git/Actions. Publication checks must inspect commit metadata/history as well as files. Required third-party attribution is retained.
- Integrity hashes are not signatures, independent review or protection from malicious installed dependencies. A public source repository is not automatically a production release.

For accidental private-data inclusion, stop new publication and preserve evidence privately. Do not post secret values or test a discovered credential. Coordinate necessary rotation/removal without pretending a new commit erases old GitHub objects or copies.
