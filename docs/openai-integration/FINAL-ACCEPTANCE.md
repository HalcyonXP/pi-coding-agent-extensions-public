# Supported surface and acceptance boundaries

Public source and a green source check are not a shipping artifact, hosted entitlement certificate or independent security review. Every review/check/build receipt must name this repository's exact source commit. No historical private receipt is included or relabelled as acceptance here.

The [milestone index](MILESTONES.md) records completed exact-source/master/copied-handoff gates. The table below describes bounded behavior, not acceptance of an arbitrary later tree.

## What each check establishes

- Repository/extension/runtime tests use fixtures, blocked/mocked network and temporary storage. They exercise genuine QuickJS/process behavior where supported; portable exclusions must be reported, not counted as passes.
- Native host tests materialize the pinned genuine upstream source/patch/catalog. Real AgentSession/approvals/hooks/lifecycle are distinct from a faux conversation transport used for deterministic orchestration.
- distribution/accept.mjs loads the extracted installed SDK/normal extension, tests native read/write/edit, contained cells, zero-text protected Web/image/native-reference editing, shell drain, reload/provider revocation, and final zero active/draining scopes. Service/auth responses are synthetic, not live entitlement.
- The nested polling case separately starts three owned timed jobs while synthetic model work continues. It checks actual installed native tool presentation, unchanged in-flight input, no quiet-poll audits, meaningful output/terminal collection, intentional abort and confirmed zero ownership. The same owned workflow requires one four-line group for three normally completed jobs, expandable original details, unchanged ordinary audit counts/history, and prominent intentional-abort results. Native UI-only fixed-event frames are labelled synthetic presentation fixtures, not execution-authority evidence. Five additional group/expand/history/error/direct frames extend the original quiet/terminal and twelve settings contracts; the original settings content remains separately preserved.
- distribution/accept-profile-framed.mjs supervises distribution/accept-profile.mjs, which launches the genuine bundled CLI in isolated profiles, checks Fast and every capability choice across actual process restart, locks/exclusions, documentation and rollback preservation. Saved choices never override native exclusions. It makes no model/service call. Require all ordered receipt frames and the complete original CLI/settings semantics, not merely successful exit or a `finished.json` file.
- The profile check additionally drives the actual installed extension's native settings renderer/theme with synthetic terminal input in normal and native-excluded contexts. It verifies inline updates, persistence, session switches and read-only exclusions without network. Rendered frames are not live user-terminal screenshots or imported user configuration.
- The seven additional actual-bundle cohorts are `web`, `media`, `imagegen`, `web-profile`, `context`, `notifications` and `notification-ack`. They do not replace the full SDK or genuine CLI gates. Normal cohorts require zero final active/draining scopes; acknowledgement faults deliberately retain exactly four quarantined scopes, not cleanup. Queue acceptance is not consumption and no crash/fsync or physical-process-state guarantee follows.
- Two local builds must agree; the exact-source Node 24 CI manifest/archive digest must be compared with supported local reproduction. A source or toolchain change requires new receipts.
- Source acceptance requires the exact reviewed head/base, all expected hosted checks, a labelled COMMENTED AI-assisted self-review, unchanged closure scope and guarded integration. Self-review is not independent approval. Failed/missing/cancelled/skipped checks are not waived.
- A [local preview handoff](LOCAL-PREVIEW.md) additionally needs accepted-merge-specific artifacts, verified copy/extraction and actual installed checks against that extraction. It is not a public upload/download, completed redistribution review or the user's active installation.
- Public release availability additionally needs explicit accepted artifact identity, provenance, upload/download verification and separate authorization. Actions uploads only provenance; it never deploys the executable bundle.

See [validation commands](VALIDATION.md). No live validation harness, credentials, account-specific response receipts or service-budget claim markers are published here. Routine checks must not invent a new hosted-service allowance or retry a previous private development smoke.
