# Reproduce validation without hosted-service calls

Use a separate checkout, existing Node 24/25 and new output paths. Windows x64/.NET Framework 4.8 are required for production containment and bundle acceptance. Ubuntu runs the applicable portable/native-host tests with explicit Windows-only exclusions. Never count a skipped case as a current-head pass.

## Focused implementation loop (not acceptance)

Follow the [batch delivery plan](DELIVERY-PLAN.md). After the session's canonical-repository/identity/guard preflight, work on a feature branch with already installed dependencies and the verified helper:

    node .github/scripts/develop-openai.mjs --list
    node .github/scripts/develop-openai.mjs coordinator unified types

Select only affected suites while implementing; use `extension`, `runtime` or `distribution` when changes warrant broader regressions. The runner accepts named suites, not arbitrary commands. Each invocation retains a new private `.pi/development/` directory with HEAD/dirty-input snapshots, raw byte logs, isolated per-suite profiles and development-only results. No existing receipt, failed attempt or installation is replaced. Child environments are established before SDK imports: fresh home/profile/temp locations, blank Git/npm configuration, OS-variable allowlist, offline flags and the existing external-fetch guard. These controls are not a general shell/network sandbox. Native SDK probes must still mock `checkAuth` and `getAuth` before requests and restore their seams.

For actual native development against a separately accepted, workspace-local SDK bundle, use `node .github/scripts/develop-openai.mjs --sdk-bundle .pi/accepted-bundle native-projection native-wait native-settings native-web`. Each suite imports the SDK only in its new isolated child, loads the **working source extension**, checks the bundle bytes/current native patch, and reuses the maintained synthetic acceptance scenarios. These results are explicitly **source-on-predecessor-SDK development**, never new-artifact acceptance. Select the SDK from a verified handoff; bundle pin validation alone does not prove installation acceptance. No source override is added to the installed-artifact acceptance entry points.

The runner neither prepares dependencies/helper nor builds/downloads bundles, contacts hosted CI, reviews, integrates or copies a handoff. Keep dependencies fixed during a run; HEAD/dirty-source drift fails the attempt, but this is not a complete installed-dependency freeze. Missing prerequisites fail visibly. Inspect retained outcomes before repeating effectful work; there is no automatic retry. Required full source, hosted, resulting-master and actual-copy acceptance below remains mandatory at completed milestones. Do not overwrite the shared full-validation receipt during focused development.
