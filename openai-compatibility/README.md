# OpenAI compatibility

The goal is [Codex-compatible observable tool behavior within Pi](../docs/openai-integration/CODEX-COMPATIBILITY.md), not just matching names. The implementation still has explicit compatibility gaps. One Pi extension provides a persistent Fast preference/shared compact footer and cohesive OpenAI capabilities. Pi **0.85.1** owns the native catalogs, models, auth, transports, pricing and cache behavior. This extension does not register replacement model/provider factories or backport Astra. Ordinary providers/tools remain available.

The locked native catalog includes openai-codex/gpt-6-astra and openai/gpt-6-astra. Authenticate normally with /login in a new isolated profile; choose the official provider/model through /model. Stock Pi supplies models/Fast support, but production Code mode additionally requires the [compatible patched host](../host-patches/pi-0.85.1/README.md).

## Settings menu

In the terminal, **`/openai-tools`** is the single OpenAI entry point, using Pi's native searchable `SettingsList`. Fast and the owned-jobs view are inside it; there are no standalone `/fast` or `/openai-jobs` commands. Values sit beside their labels, with a description for the selected row. Use Up/Down, type to filter, Enter/Space to change, or the native mouse controls. The menu stays open after changes. **Changes apply immediately; Esc closes, it does not undo them.** Narrow terminals ask you to widen the view rather than change invisible controls.

Fast and all four capability choices are saved for this Pi profile, across reload, new sessions and CLI restart. A fresh profile still defaults to Image generation on and Web, Unified exec and Code mode off. Saved choices are distinct from effective activation: current route, tool ownership/exclusions and passive native preflight are checked again; every actual invocation still requires current authority and, for hosted tools, authentication/entitlement. An inactive Fast preference remains visibly on with the reason in its description. Unavailable/excluded/conflicting capabilities are read-only and explain why; neither this menu nor on commands can bypass rollback exclusions. Route, configured OAuth and native-runtime rows are passive information, not entitlement or execution authority. Runtime preflight distinguishes ready, busy and draining. Status is checked on open and after changes, not a live job monitor.

Opening the menu never refreshes credentials, launches a worker/compiler or calls a model/service. Pending updates show `applying…`, not optimistic success; failures refresh actual values, or freeze unknown state until reopened. Close/session/model changes revoke pending menu work. Tool preference changes preserve the existing cancellation behavior for running capability work. Pi's own `/settings`, model selection, ordinary tools and Fast/footer ownership are not replaced.

The **Jobs** row opens a same-session snapshot inside this menu. Enter a job to choose Keep or confirm cancellation; unconfirmed cleanup stays visible and can only be retried explicitly. Refresh updates the snapshot and resets the jobs filter; Esc returns to the parent list without losing its filter. Completed effects are never undone. Closing/model/session changes revoke pending UI actions; no job is launched by inspection.

Explicit subcommands remain available below. `/openai-tools fast status`, `/openai-tools jobs status` and `/openai-tools status` always produce text. Bare commands in RPC/non-terminal contexts retain text status rather than open a modal. `/openai-tools fast` or `/openai-tools jobs` focuses that row in the same TUI menu.

## Independent controls

- /openai-tools fast on, off, toggle or status: persistent preference; eligible official models receive service_tier: priority. Priority usage/cost is separate from subscription capability use and ordinary conversation billing. Unsupported routes remain inactive.
- /openai-tools status: passive availability inspection; no compile, worker launch, auth refresh or request.
- /openai-tools imagegen on|off: eligible official-route image generation is initially enabled.
- /openai-tools web_search on|off: fixed, bounded subscription Web profile; initially off.
- /openai-tools unified_exec on|off: exec_command/write_stdin; initially off.
- /openai-tools code_mode on|off: paired exec/wait on a compatible host/runtime; initially off.
- /openai-tools background-wait status or <milliseconds>: saved empty-poll ceiling, integer5000–300000 ms (default300000). Also available as the Background wait ceiling settings row. Future direct/nested polls only; no job cancellation, tool activation or process-budget change.
- /openai-tools jobs status and /openai-tools jobs cancel <session_id>: inspect or explicitly cancel this session's owned Unified exec jobs. The existing --fast startup flag, saved preference and shared footer remain; only redundant command entry points were removed.

Capability choices are independent saved opt-ins. The profile's `openai-compatibility-capabilities.json` contains only four booleans in a versioned record; Fast's existing `openai-compatibility.json`, startup flag and legacy migration are unchanged. Saving one choice preserves the other saved choices. Each session loads its profile snapshot; this is not automatic cross-process live synchronization. Malformed/unreadable capability state restores all four off, reports the problem and is not silently overwritten. A failed save leaves the current selection unchanged. Atomic file replacement is not crash recovery or a cross-process transaction.

The separate `openai-compatibility-unified.json` saves `{version:1,maxBackgroundWaitMs:300000}` by default when explicitly selected. Missing state uses that default without writing. Invalid state is preserved and blocks Unified activation until repaired and reloaded; other capabilities and Jobs cancellation remain separate. Failed saves leave the current ceiling unchanged. Existing pending polls retain their captured wait; other sessions load saved changes on restart/reload. See [background wait semantics](../docs/openai-integration/NATIVE-UNIFIED-CONTRACT.md#background-wait-preference).

Only selectable preferences persist—not Jobs, cells, runtime availability, credentials or execution authority. Model/provider/lifecycle changes still cancel/revoke pending work; switching away and back cannot revive it. Changing a tool choice retains the existing cancellation of running capability work. Recorded history and generated originals are not erased.

## Capability contracts

Hosted imagegen/Web use Codex subscription authentication only, with official conversation and service configurations checked before auth. No paid API fallback. Endpoint/model names alone do not establish trust; overridden/proxied providers are denied. Account entitlement and protocol availability may vary.

Imagegen accepts prompt, up to five workspace-local referenced_image_paths OR up to five recent pathless conversation images, and an optional safe workspace-relative PNG destination. Protected nested edits use native referenced_image_refs, not guest-chosen filesystem substitution. Service settings/model are fixed and automatic, not arbitrary API model/size/quality/background selectors. Canonical PNGs remain immutable; existing destinations are not overwritten. Ambiguous failures do not trigger automatic retries.

Web accepts one search query or initial absolute-public-URL open per call, using fixed gpt-5.4-mini with a short/low bounded profile. Domain filters are advisory, not enforcement. Preserve the full bounded source records and cite original URLs; no general find, deep research, opaque continuation or native citation-widget parity is promised.

Unified exec delegates full-OS shell commands, not a shell sandbox or PTY. On Windows x64 it requires the verified prebuilt helper: PowerShell loads its independent Job Object type as a library, with no per-launch compilation/download or unverified fallback. The restricted coordinator executable entry point and limits remain unchanged. Windows uses supervised Job Object/held-parent identities and a private readiness acknowledgement; POSIX process groups do not establish Windows crash equivalence. Exact native scope/context identity owns nested returned jobs and stdin, not a returned string ID. Unconfirmed cleanup stays draining.

Code mode runs a bounded QuickJS async-function body, not ambient Node/V8. `exec` uses Pi's existing native custom grammar API: send raw JavaScript, with optional first-line `// @exec: {"yield_time_ms":1000,"max_output_tokens":10000}` controls. Native internal/SDK input is exactly `{code}`; former top-level options now fail visibly rather than disappearing from custom-call history. LF/CRLF pragmas are supported. Code requires the selected native Responses model's explicit grammar-tool capability; an unavailable choice is retained without a JSON-provider fallback. `wait` remains JSON with cell_id, yield_time_ms, max_tokens and terminate. Direct exec/wait results now contain script status, measured per-call wall time and literal coordinator text, not a JSON envelope. SDK/RPC consumers read the retained structured `details`, including `code_result: {version:1,wall_time_ms}`, rather than parsing content as JSON. The native `{result,isError}` wrapper remains available through `nativeTools`; default guest `tools` may project recognized results. Direct Unified exec has a separate result contract. See [native input/result boundaries](../docs/openai-integration/NATIVE-CODE-CONTRACT.md). Image generation retains its native image and canonical path if a later optional destination copy fails; a visible warning and `copyStatus: "failed"` distinguish that case from successful copying. Cancellation and failed canonical saves remain refusals. Capability arguments are snapshotted after native hooks and validated before asynchronous work.

[Default Unified projections](../docs/openai-integration/CODE-RESULT-PROJECTION.md) return `{wall_time_seconds,output,exit_code?,session_id?}` through `tools`; `projectedTools` is now an identical alias. Check for top-level `output`: errors, loss, hook changes and protected evidence retain full native wrappers. **Migration:** wrapper-based Unified scripts must use `nativeTools` for the previous `{result,isError}` contract. PR #32 accepted this Unified migration without changing native authority or collection budgets; it is not full Codex API parity. Batch B working source additionally returns normal `web_search` text only after native protected publication and original RPC admission. Check `typeof r === "string"` for Web; changed/oversized replies retain full wrapper/evidence-view fallback. The untrusted-content label and opaque source text survive. Choose `nativeTools` on the original invocation for raw metadata—never repeat a service action just to change its view. New Web work is not yet installation-accepted.

Working-source default `tools.imagegen` also projects recognized normal replies to `{image_url:ownedImageRef,output_hint}`. This Pi reference is not upstream inline bytes or a remote URL. `generatedImage(r)` publishes the original and a bounded unverified hint; call it only when the projected field exists. Errors/hooks/copy failures retain full wrappers. Choose `nativeTools.imagegen` for raw metadata before the original invocation, never regenerate to change views. Canonical originals and full native warnings remain protected.

Helpers include tools.NAME(args), ALL_TOOLS/TOOL_NAMES discovery, text, store/load, image/generatedImage/evidence, yield_control, exit and bounded setTimeout/clearTimeout. Named cell tools accept objects or JSON strings encoding objects; image accepts native image-reference strings/blocks or bounded canonical inline PNG/JPEG/GIF/WebP (data URL, image_url object or image content block). Inline data is capped at 32KiB decoded, with unchanged aggregate/native limits, and labelled guest-provided in protected publication; it does not prove generation/save. No network URLs, paths or detail hints. References are issued only after publication and retain native context ownership/expiry. See [media input boundaries](../docs/openai-integration/MEDIA-INPUTS.md). [Coordinator argument/helper boundaries](../docs/openai-integration/CODE-COORDINATOR-COMPATIBILITY.md) retain native validation and suppress queued work after disposal. [ALL_TOOLS](../docs/openai-integration/CODE-TOOL-METADATA.md) is a frozen snapshot of native `{name,description}` records, not permission, schemas or callbacks. Descriptions are bounded without truncation (16KiB each,64KiB total), and the complete source/metadata start must fit the unchanged400KiB frame before scope admission. At most 32 eligible native tool names are exposed; exec/wait recursion is denied. Zero guest text cannot suppress protected finalized source/image evidence. Coordinator restrictions do not constrain the OS permissions of explicitly delegated native tools.

`text()` remains primitive-only: project an array of names to a joined string or use explicit `JSON.stringify` when structured output is needed. Unhandled text/image/timer helper misuse reports fixed corrective hints, never arbitrary guest exception properties. Caught errors remain catchable. Unambiguous hyphen-to-underscore `tools` aliases dispatch the original native name; exact native entries win, collisions omit the alias, and metadata/authority do not change. See the [helper feedback and alias contract](../docs/openai-integration/CODE-COORDINATOR-COMPATIBILITY.md).

For people, use `text()` with concise labelled lines of actual collected output, exits/errors and requested aggregate counts; do not dump entire delegated results or repeated initial snapshots by default. Preserve warnings and output-loss facts. Use JSON only when requested or needed for machine processing. The native exec/wait card displays cell status and literal coordinator text, with full returned metadata behind the existing tool-expansion control. Routine previews show eight visual lines plus an explicit overflow indication. Errors, draining, termination and already-omitted guest bytes remain prominent; expansion cannot recover omitted output. Cell completion does not establish success of every child job. The renderer accepts exact historical JSON/details or exact current text/details, and preserves ordinary visible fallback for unfamiliar, mismatched or hook-added content. Rendering/expansion does not itself change wire/history/protected evidence or guess human summaries from arbitrary JSON. The direct-output transition changes future exec/wait content; historical completed output and immutable bundles are not rewritten. Wall time measures this invocation, not cell age, child runtime or billing.

### Returned jobs, capacity and completion

Direct `exec_command` / `write_stdin` results contain process status, measured time for that awaited call and literal returned shell text. Native structured fields remain in `message.details`, with `unified_result: {version:1,wall_time_ms}`; direct SDK clients no longer parse content as JSON. An exited process can retain an ID solely for unread output. Readiness, termination and dropped bytes remain visible, even with empty output. Native nested wrappers retain JSON/details through `nativeTools`; default Unified guest results can project them. Protected completion reports retain their separate identity and content. Native ordinary rendering/expansion is unchanged; no heuristic summary, history migration, token telemetry or new authority is added. See the [direct Unified contract](../docs/openai-integration/NATIVE-UNIFIED-CONTRACT.md).

`exec_command` may return `running: true` and a `session_id` before the Windows supervisor is ready. `supervisor_ready: false` is a startup observation, not proof the command ran or failed. Poll with `write_stdin`; do not replay the launch to wait for it. The patched host shares **two active/draining durable scopes** across direct jobs and Code mode. The separate four-process extension limit does not grant four direct-job slots. A third direct start can be refused while two scopes are occupied; do not clear ownership or increase limits to force admission.

Direct jobs remain pollable in their original conversation/native context while other ordinary tools run. Cell jobs additionally require the original cell scope and close when that cell completes. IDs cannot adopt a different context/cell. Model/session/registry changes, abort/reload and expiry can revoke jobs; keeping the terminal open does not prove the original native context remains current. Native scopes last at most six minutes; the shell manager retains its five-minute idle and ten-minute total execution ceilings. **Completed records no longer expire on a one-minute last-poll timer.** Up to eight records retain at most 1 MiB each; starting another job may evict an eligible completed least-recently-collected record, never one with unsettled/failed publication. Collection, explicit cancellation and reset also remove records. A terminal result without a `session_id` has been consumed.

On the compatible patched host, a direct job whose initial response is running publishes **one asynchronous terminal report** through genuine protected native evidence. It correlates the original invocation and job, reports exit/termination, and snapshots up to 64 KiB of **uncollected output**, with dropped/remaining byte counts. It is untrusted tool output, not a new command, complete transcript, or the fixed diagnostic metadata channel. Reporting does not consume polling output. Physical child close and publication/native settlement are separate; unconfirmed reporting remains visible in Jobs, blocks new launches, and is not silently retried or cleared.

The native history/UI delivers immediately when idle or queues safely while streaming; the next safe model request receives the report. It **does not interrupt an in-flight request, start an idle assistant turn, or stream incremental output**. Poll for readiness/input/remaining output; nested Code-mode jobs still use their original cell's polling/cleanup. The Jobs view remains a passive snapshot, not a subscription. No reload/crash job resurrection is added. If polling reports unknown/expired/foreign, preserve the call timeline, redacted arguments/results and passive settings/Jobs state. That error does not establish whether the command ran; never automatically replay possibly completed effects.

### Quiet local polling

With the matching updated patched host, routine cell-owned `write_stdin` calls with empty input and unchanged empty-running output create no TUI cards or ordinary audit messages. They still execute through the native gateway and count against every existing call/process/lifetime limit. Direct/model-issued calls are never hidden. Input/control, updates, output, truncation, errors, termination and terminal results remain visible; revealed local results are labelled **Local job update**. Native SDK/RPC events retain their presentation hints and full accounting.

This removes poll-derived audit context as well as visual noise. It is not a live quota meter: generating coordinator code, other model work, meaningful audits and anything explicitly printed into `exec`/`wait` output still use model input/output normally. Prefer printing meaningful changes rather than each unchanged poll. Ordinary audits say **returned**, not completed: a call returning a running job is not job completion. Without matching native metadata, older hosts stay visible instead of guessing. No automatic nested terminal publisher, idle model turn, polling-budget increase or cleanup bypass is added.

### Code mode diagnostics and desktop tasks

Code mode is not a built-in computer-use/desktop-control service. PowerShell automation may be deliberately delegated, but foreground focus, window titles, permissions and application lifecycle need their own verification. Normal child processes are owned: finishing a cell closes its returned shell jobs/descendants, so launching a background GUI does not create an independent persistent desktop session. This does not establish the cause of any earlier failure; do not disable cleanup or automatically replay a partially completed action.

Use `await nativeTools.NAME(args)` when reading raw `{result,isError}` wrappers: Unified data lives under `result.details` (`output`, `running`, `exit_code`, `session_id`). Default `tools` instead projects recognized normal Unified output; handle its full-wrapper fallback explicitly. Neither shape proves that a GUI action succeeded. Poll the corresponding `write_stdin` within the original owning cell; `wait` polls the cell rather than adopting a shell job. Emit non-sensitive checkpoints where needed.

A failed cell retains its stable error code plus bounded `result.diagnostics`: guest phase (initialize/compile/execute/await, or unknown when not observed), delegation/result/error counts, the last-started delegation's fixed category and bounded shell observations. Concurrent completions do not relabel another call's result. These fields never include exception messages/stacks, source, commands, paths, IDs or output text. `effects: not_determined` is intentional: neither a thrown guest error nor a closed process proves which external effects occurred. Raw guest exceptions remain withheld, including objects with hostile getters. Native cleanup/publication authority and output limits are unchanged.

See [architecture/limits](../docs/openai-integration/ARCHITECTURE.md), [supported/deviating surface](../docs/openai-integration/FINAL-ACCEPTANCE.md), and the [isolated profile guide](../docs/openai-integration/PRIVATE-RELEASE.md). Never load the retired standalone imagegen directory as a second implementation or select an unrestricted fallback.

## Development

From the repository root: npm ci --ignore-scripts --prefix openai-compatibility, explicitly prepare the pinned compiler inputs on Windows, then node .github/scripts/validate-openai.mjs. The validator builds/verifies the prebuilt assembly before native shell tests; standalone Windows `npm test` also needs that explicit build first. This uses offline guards and temporary storage. Source tests are not a binary release, live-service proof or permission to modify an active installation. [Full host/build commands](../docs/openai-integration/VALIDATION.md) use separate prepared directories and pinned inputs.
